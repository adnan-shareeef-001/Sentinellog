# SentinelLog Cybersecurity & SOC Glossary

Welcome to the SentinelLog security glossary! As a beginner, security terminology can feel overwhelming. This living document explains every concept encountered in this project in plain, conversational English.

---

## 🏛️ SOC & Operations Fundamentals

### Security Operations Center (SOC)
A centralized team and command facility responsible for continuously monitoring, detecting, analyzing, and responding to cybersecurity threats across an organization's computers, servers, and networks.

### Telemetry
The streams of digital activity records and measurement data collected from devices across a network (e.g., login attempts, web requests, network packet headers, process executions).

### Log
A raw, unparsed record written by an operating system, application, or network device describing an action that occurred (e.g., a single line written to `/var/log/auth.log`).

### Event
A structured, normalized representation of a log. While a log is unstructured text, an **Event** is parsed into specific fields (such as timestamp, source IP, username, and action).

### Alert
A notification generated by a detection engine when one or more events match a security rule or policy (e.g., "15 failed SSH logins in 1 minute from IP `198.51.100.5`").

### Incident
A verified, high-confidence security event or cluster of related alerts that indicates an active or attempted breach requiring human investigation and containment.

### Triage
The process of reviewing incoming alerts to determine their priority, validity, and impact. A Tier-1 SOC analyst inspects the evidence to answer: *Is this malicious? Is it a false alarm? Does it need immediate escalation?*

### False Positive (FP)
An alert triggered by benign, normal activity (e.g., an employee who forgot their password 5 times triggering a brute force alert).

### False Negative (FN)
A real cyber attack that slipped through undetected because no rule or anomaly detector identified it.

### True Positive (TP)
A legitimate security alert that correctly flagged actual attacker activity.

### True Negative (TN)
Normal system activity that was correctly evaluated and ignored by the detection engine.

## 🎯 Detection Engineering & Threat Concepts

### Detection Engineering
The defensive discipline of researching attacker behavior, identifying telemetry sources, and writing robust rules/algorithms to catch threats while minimizing false positives.

### Indicator of Compromise (IoC)
A piece of digital forensic evidence that indicates a system may have been breached (e.g., a known malicious IP address, a malware file hash, or a phishing domain).

### MITRE ATT&CK®
A globally accessible knowledge base of adversary tactics, techniques, and procedures (TTPs) based on real-world observations. It provides a common language for classifying attacker behavior (e.g., Technique `T1110.001` = *Password Guessing*).

### Brute Force Attack
An automated trial-and-error attack where an adversary attempts to guess credentials by trying hundreds or thousands of username/password combinations.

### Password Spraying
A stealthy variation of brute force where an attacker tests a single common password (like `Winter2026!`) across hundreds of different user accounts to avoid triggering account-lockout thresholds.

## 🔒 Software Security & Threat Modeling

### Log Injection (Log Forgery)
An attack where an adversary submits malicious input containing newline characters (`\n` or `\r`) into an application (like a login form). If written unsanitized to a log file, it creates fake log entries that can mislead security analysts or confuse log parsers.

### Regular Expression Denial of Service (ReDoS)
A Denial of Service vulnerability caused by using an inefficient, non-deterministic regular expression with nested quantifiers. When evaluated against malicious input, it can trigger catastrophic backtracking, freezing the CPU at 100%.

### Provenance (Data Provenance)
The traceable record of the origin, custody, and chain of evidence for a data point. In SentinelLog, every alert tracks exact file paths and line numbers so analysts can defend their findings in an audit or court of law.
